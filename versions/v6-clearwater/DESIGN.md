# Design — v6 "Clearwater"

## 1. The judge brief (`tools/brain_judge.py`, `judge/lenses.json`)
Problem: a judge that does not know what it was given cannot say what it could not check. v5 cut the packet at 120,000 characters without a word, showed nothing of binaries, and started every round from zero.

The packet now has fixed sections, in this order:
- **0 What you received** — one manifest row per input: path, kind (artifact or maker claim), bytes, and `full` / `excerpt: N of M chars (characters a–b cut); full file: ./artifacts/NN-name` / `not inlined (image/PDF | binary); open ./artifacts/NN-name` / `MISSING`. Then one line on what else is in the packet and one on what is not in it by design (chat, reasoning, checkpoints, unlisted files).
- **1 Goal** — the frozen contract, then a requirement ledger: id, text, its check, its Tier-0 state.
- **2 Errors and risk signals** — Tier-0 results; shell results from `evidence.jsonl` that look like errors, with "no clean rerun recorded" (an error followed by a clean run of the same command is only counted); hook warnings; the previous round's failed checks, non-pass verdicts, flaws and unsupported claims, each to be re-checked. The brain's own commands are left out, because their arguments can carry the maker's notes (blindness holds; tested).
- **3 What the session changed** — edited files, and which were not submitted.
- **4 Lenses** — per scope class, what usually goes wrong (engineering/3D/simulation, website, brand/packaging, research, CV, system). Hints for `flaws`; the instruction forbids failing a requirement on a lens.
- **5 Artifacts**, then the maker's summaries under the v3 "claims, not evidence" heading.

Budget: the fixed sections are measured first; the rest is shared between the text artifacts, smallest first, so short files are whole and long files get head (70%) and tail (30%) with the cut named. The sealed folder holds copies of every artifact (≤ 25 MB each, 80 MB total), so a judge with file access opens what the packet could not show.

Schema additions: `fix` per verdict, `inputs_missing`, `unsupported_claims`. `review_verdict()` then checks the answer: a contract requirement with no verdict becomes `not_checked` and turns `pass` into `inconclusive`; `pass` above a failed blocker/major becomes `fail`; a `pass` whose quoted evidence is not in the packet is flagged. None of these can turn a fail into a pass. The exact brief is saved as `judge-brief-NN.md`; the verdict record lists the inputs and how each was shown. `--preflight` runs Tier 0 and the accounting with no model call. `--export DIR` writes the same packet, schema and sealed copies as files, for a judge that someone runs by hand (`--sealed-only FILE…` sends long code as full copies without inlining it, so the documents stay whole in the packet); `--record FILE --judge-name NAME` then files its answer as a normal round (Tier 0 again, same code review of the answer). The folder is sealed before the packet is final (`prepare()`), so a copy that failed is taken out of the packet and the manifest; `artifacts/SEALED.txt` lists what is really there. Quotes are paired in order (`quoted()`), each one checked on its own against the packet and the full artifact texts. A `cmd` check that exits 0 while printing an error is shown as `PASS?`.

`judge_typed.py status` separates "Tier 1 disagreed with itself" (rewrite the question) from "no threshold is live" (calibrate).

## 2. The token layer
- **Project map (`tools/brain_map.py`)** — `query`, `outline`, `slice`, `who`, `build`, `stats`. Python through `ast`; JS/TS, HTML (ids, inline `<script>`/`<style>` with real file line numbers), CSS, GLSL, Markdown and JSON through line scanners. Incremental by size and mtime; maps live in `index/maps/` (rebuildable, git-ignored). Answers are pointers `path:Lstart-Lend` under a token budget; `slice` prints only that range. `Brain System/self` is never walked or sliced. Every call logs answer tokens against whole-file tokens (`state/map-savings.jsonl`) as an upper bound of the saving; the digest prints the week's sum. Compared with a model-built knowledge graph: free and instant to build, cannot paraphrase or invent; no semantic layer.
- **Hooks that say a thing once (`tools/brain_hooks.py`)** — `state/hook-seen.json` remembers per conversation the flow state it announced and the skills and notes it showed. The flow line returns only when the state changes (plus a ten-word nudge every 15 messages); a skill or note already shown is not shown again. Machine-made messages (`<task-notification>`, `[SYSTEM …`) get nothing. Skill lines use `$BRAIN` for the root and 100-character descriptions. `BRAIN_HOOK_VERBOSE=1` restores the old behaviour.
- **Capsule (`brain_session.py capsule`)** — goal, requirements with their last state, the last five checkpoints, files touched, open errors, the judge's fix list, what was reused; built from records, ≤ 2,400 characters, rewritten by every checkpoint. `brain_start.py` prints it instead of the card when the start hook reports `compact` or `resume` for a conversation with an open session, and clears the hook memory so skills are offered once more.
- **Section reads (`brain_fetch.py --outline | --section`)** and **one entry point (`tools/brain.py`)**, which forwards arguments and exit codes.

## 3. Memory quality
- **Learn** — the queue takes the Brain Summary's proposed lesson, then bullets under a "Lessons" heading, three per session at most. Gotchas, fixes and "what worked" go to the ledger under their own line. A retrieval gap is a gap report, not a lesson. A shown skill counts as "used" when its SKILL.md was read, or the summary names it: a multi-word name as a whole word, a one-word name only in backticks or next to the word "skill" (before: any occurrence, so `ship`, `start`, `fix` were "used" in most sessions and fed the router's telemetry boost).
- **Dream** — a reflection is the whole sentence that carries the signal word (with the sentence it refers back to, or the one after); a tool error is recorded only when its signature repeats; hook errors are one line per distinct error with a count; reflections and the graph map are `type: log`, and logs are never retrieval answers (`brain_route.py`, `brain_hooks.py`). A bridge needs a shared word in title or tags. The LaunchAgent no longer passes `--apply-links`. The "autoresearch" stage is documented as what it is: a counter.
- **Sleep** — the digest shows the eight strongest candidate lessons (structured first, then newest) and counts the rest; it adds a cost line (sessions, median and heaviest token totals, map savings).

## 4. Routing
- Thin-prompt evidence gate (the only router change): with one or two content words a skill is offered only when two words hit it and one is in its name, or a rare word hits its name and nothing else in the message points elsewhere. An exact multi-word skill name always passes.
- `variants()` is v4's plural matching moved into one function. A verb ↔ -ing rule was built and withdrawn: on the owner's 63 real requests it changed the offer for 32 with no way to tell better from worse.
- `tools/route_real.py`: the router on the owner's own words — every closed non-private session's verbatim request (offered skills per session, comparable across router versions), the sessions with a real SKILL.md read (the only true label in the records), and his typed messages of at most four words from the transcripts. Output holds ids, skill names, hashes and counts, never message text. Reported, never a gate.
- Holdout sets (`state/eval/prompt-skills-holdout*.json`, `route_eval.py --holdout`): written by the reviewer, reported, never a gate; a test fails if a holdout prompt appears in the router's or the hook's code. They are not blind for v6's own gate; `evidence/holdout-provenance.md` says exactly what is.
- Left as found, on purpose: the hard-coded noise regex and the two special cases in the scorer. Removing them is a retuning job for the Gym against the holdouts, not a review edit.

## 5. Subagents and Codex
`brain-verifier` (new): preflight first, then every checkable claim of the summary against artifacts, evidence and Tier 0; `supported` needs a quotable line. Scout: map first, and a pointer must be a range it opened in that run. Worker: slice instead of whole-file reads, re-read each changed range once. Scribe: starts from the capsule, one lesson at most, fields aligned with the close template. Codex has no named subagents; the same abilities are tools (`BRAIN map`, `BRAIN preflight`), and the card and protocol say so.

## 6. The session linker
`cmd_post` linked a conversation to any session id found in the output of a command that contained the words `brain_session.py` and `new` — including a script that only printed them. Now the command must invoke `new` itself (heredoc bodies do not count) and the session must be minutes old.
